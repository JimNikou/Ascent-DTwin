How the Ascent-DTwin platform works: data flow, integrations and intelligence features.

Architecture

Ascent-DTwin is a lightweight digital twin library manager inspired by INTO-CPS DTaaS. It runs as a Docker Compose stack:

  • API (FastAPI) — twin CRUD, telemetry ingestion, health scoring, anomaly detection, web UI.
  • Mosquitto MQTT — live telemetry bus for ESP32 and other devices.
  • InfluxDB — time-series storage for telemetry history.
  • Grafana — dashboards with per-twin and per-sensor panels.
  • JupyterLab — notebooks for analysis and anomaly detection experiments.

Data flows: device → MQTT / HTTP → API → InfluxDB → Grafana / Jupyter. The API keeps a rolling in-memory window for real-time anomaly detection and health scoring.

Ingesting telemetry

Every twin has an MQTT topic and an HTTP endpoint. Publish JSON with the twin's sensor fields:

  • MQTT topic: ascent/<twin-id>/telemetry (port 1883)
  • HTTP: POST /api/twins/<twin-id>/telemetry with a JSON body
{"temperature": 23.4, "humidity": 48.2, "pressure": 1012.1}

Unknown twins are auto-registered on first MQTT message (zero-touch onboarding).

ESP32 setup

Use the ESP32 Firmware & Topic button in the Twin Library sidebar to get a ready-to-flash Arduino sketch snippet for the selected twin. The full example lives in examples/esp32/esp32_telemetry.ino. Point the sketch at your PC's IP (Docker host) on port 1883 and publish to the twin's topic.

Grafana

Open Grafana from the top bar. The Ascent-DTwin — Live Telemetry dashboard has two dropdowns:

  • Twin — pick any twin that has data (auto-populated from InfluxDB).
  • Field — pick one or more sensor fields; a chart is generated per field automatically.

Jupyter

Open JupyterLab from the top bar (token ascent). Notebooks:

  • 01-ascent-demo.ipynb — query telemetry from InfluxDB and plot it.
  • 02-anomaly-detection.ipynb — Isolation Forest anomaly detection + health score.

Both notebooks auto-select a twin with data (esp32-demo if present, otherwise the first twin).

Twin health score

Each twin gets a 0–100 health score computed on demand from three components:

  • Freshness (40) — how recently the last point arrived (≤10s = 40, ≤60s = 30, ≤5min = 20, ≤30min = 10).
  • Volume (30) — points received in the last 5 minutes (≥50 = 30, ≥20 = 20, ≥5 = 10).
  • Anomaly rate (30) — share of flagged points in the window (0% = 30, <5% = 20, <20% = 10).

Status: healthy ≥ 80 degraded ≥ 50 critical < 50. Health is tracked per twin and shown on cards, in the detail view and on the dashboard.

Anomaly detection

The API computes a rolling z-score per sensor field (last 200 values). A point with |z| > 3 on any field is flagged as an anomaly: it gets a red dot on the live chart, counts against the health score, and appears in the platform activity feed. Anomalies are also visible in the Jupyter notebook using Isolation Forest.

Troubleshooting

  • No data in Grafana? The Twin dropdown only lists twins with data in the last 7 days. Generate synthetic data or publish telemetry first.
  • UI changes not visible? Static files are baked into the API image — run docker compose up -d --build api and hard-refresh (Ctrl+F5).
  • Jupyter token? ascent.
  • Grafana login? admin / ascent-admin.
  • ESP32 cannot connect? Point the sketch at your PC's LAN IP (the Docker host), not localhost.
  • Health shows critical? The twin is not sending data — check the MQTT topic or generate synthetic data.

About Ascent-DTwin

Digital twin library & intelligence platform — International Hellenic University.

Project

Ascent-DTwin is a lightweight digital twin platform for managing device twins, collecting live telemetry and deriving intelligence (health scoring, anomaly detection, analytics). It is built as a research demonstrator at the International Hellenic University (IHU) and is inspired by the INTO-CPS Association's DTaaS architecture.

Capabilities

  • Digital twin library with full CRUD (create, view, edit, duplicate, delete).
  • Live telemetry ingestion over MQTT and HTTP with zero-touch auto-registration.
  • Time-series storage in InfluxDB with Grafana dashboards.
  • Real-time anomaly detection (z-score) and per-twin health scoring.
  • Jupyter notebooks for analysis and ML-based anomaly detection.
  • Synthetic data generator for demos and development.

Technology stack

  • Backend: Python / FastAPI
  • Messaging: Mosquitto MQTT
  • Storage: InfluxDB (time-series)
  • Visualization: Grafana, Chart.js web UI
  • Analysis: JupyterLab (scikit-learn)
  • Deployment: Docker Compose

Context

This platform is developed in the context of cybersecurity research at IHU, demonstrating how digital twins can be used to monitor, analyze and secure connected systems. The demo library ships with six example twins covering industrial, agricultural, IT and utility scenarios.
